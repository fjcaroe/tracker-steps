# T112 — diagnóstico de documentos de proveedor

Revisión del 23-10-2026. **Pendiente de identificar el proveedor del caso;
ticket abierto. No hay publicación de producto ni cierre.**

Se leyó el adjunto completo y la respuesta humana disponible. La captura muestra
una factura nueva con proveedor vacío. Se reprodujo ese estado y se comprobó
que el código nativo de `l10n_latam_invoice_document` calcula la lista de tipos
solo cuando existen diario, uso de documentos y proveedor. La extensión
`l10n_cl` filtra además por clasificación tributaria y país del proveedor.

En Desarrollo y la compañía operativa canónica de Cerro El Plomo:

- El diario de compras tiene habilitado el uso de documentos y el país fiscal
  es Chile. El menú y el formulario efectivo son accesibles con el perfil
  contable existente, sin superusuario ni ampliación de permisos.
- El formulario nuevo no ofrece tipos mientras el proveedor está vacío.
- Al seleccionar un proveedor chileno existente con clasificación tributaria
  completa, aparecen los documentos y se selecciona el código 33.
- Se verificaron las versiones efectivas: `account` 18.0.1.3, `l10n_cl`
  18.0.3.1 y `l10n_latam_invoice_document` 18.0.1.0. Las funciones nativas
  revisadas tienen el mismo hash en ambos destinos.
- Se detectó un proveedor chileno en Cerro con clasificación o RUT incompleto.
  No se modificó su clasificación sin identificar el caso y sus datos reales.

La revisión gráfica en Desarrollo reprodujo el adjunto desde el tablero de
Contabilidad: el selector vacío se llena al elegir un proveedor y ofrece
Factura Electrónica (33), entre otros. El borrador se descartó sin guardarlo.
No se contabilizó ninguna factura ni se alteraron datos o configuración.

Se preguntó en este chat cuál es el proveedor afectado. Si el selector sigue
vacío después de elegirlo, ejecutar el diagnóstico con `VENDOR_ID` para ese
registro y revisar su país, RUT y clasificación; no eliminar el dominio nativo
ni asignar una categoría tributaria por conjetura. Una futura corrección de
código/configuración deberá cumplir la validación en copia y publicación
canónica correspondiente. No se ha probado todavía la contabilización del
documento denunciado.
